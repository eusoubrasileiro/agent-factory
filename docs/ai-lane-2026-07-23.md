# AI-engineering lane — design note (2026-07-23)

**Status: ratified by Andre 2026-07-23.** Normative text lives in
`skills/mission-plan/SKILL.md` §4 (the lane rule) and the product integrity
reviewer (`Ratified-by:` trailer). This page records the rationale only.

## Why a lane, not a new pipeline

Gates attach to **what changed**, not to which workflow touched it. Three kinds of
change differ on both the proof axis and the owner-involvement axis:

| Kind | Proof that catches its defect class | Owner involvement |
|---|---|---|
| CRUD / schema / BFF / UI | canonical `pnpm test:e2e` (real infra), Playwright | ratify intent once, judge PASS/FAIL |
| Mechanical / trivial | deterministic gate | none |
| **AI engineering** (bot graph, prompts, tools) | **evals + golden transcripts + chat MCP probe** | **in the design loop, pre-build** |

Motivating incident (wahub, 2026-07-23): an enum-cast SQL no-op and a bot
promotion that could tag a non-lead as a lead both passed units + tsc + lint.
They are from **different rows** — the first needed real Postgres (now closed by
the canonical `test:e2e` umbrella), the second is invisible to any e2e suite and
was caught only by eval/doctrine review. One gate cannot cover both.

## The lane, in one paragraph

A mission touching agent surfaces suspends fire-and-forget: the orchestrator's
contract carries a **design brief in markdown** (graph delta, prompt/tool-description
diffs, SDK-pattern citation — knowledge protocol checked first), Andre ratifies the
brief **before** build, the **eval gate** is the lane's real-stack proof, and every
bot-path commit carries `Ratified-by: Andre` so the pre-push integrity reviewer can
see the ratification instead of forcing `--no-verify` (the 2026-07-08 SDR-ship wound).

## Fit with existing law

- Constitution non-negotiable #1 (one human gate) — unchanged; this lane moves the
  gate earlier, it does not add a second one.
- D-03 — Tenant A reviews bot config as owner before it goes live on a real client.
- Agent surfaces Andre reviews are authored in `.md`, never inline strings.
- Eval cost discipline — first run of a new eval: 1–2 threads, scale as they pass.

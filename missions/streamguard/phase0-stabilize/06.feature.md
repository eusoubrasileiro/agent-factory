# Feature 06 — /24 guard + dashboard bind/auth · mission phase0-stabilize

## Intent

Two independent safety gaps. Clients are indexed by the last octet of their
IP, which silently collides on any subnet wider than /24 — two devices would
share one quota counter and the daemon could block the wrong one. And the web
dashboard binds every interface with no authentication, publishing the whole
family's usage to anything that can reach the host.

## Scope — the ONLY files you may touch

- `src/streamguard.c`
- `scripts/web/app.py`
- `scripts/streamguard-web.service`

## My assertions

- **A10**: startup refuses a netmask other than /24 with an explanatory error
  instead of silently mis-indexing clients — proven by

  exiting non-zero with a message naming the limitation.
- **A11**: the dashboard binds `127.0.0.1` by default, honours
  `STREAMGUARD_BIND`, and warns when bound non-locally without
  `STREAMGUARD_WEB_PASSWORD` — proven by inspection plus runs with env
  overrides.

## Pre-assembled context

**The /24 assumption.** `src/streamguard.c:158-161`:

```c
/* Get client index from IP (assumes /24) */
STATIC int get_client_index(uint32_t ip) {
    return ntohl(ip) & 0xFF;  /* Extract last octet in host byte order */
}
```

`clients[MAX_CLIENTS]` with `MAX_CLIENTS 256` (`src/streamguard.h:29`). The
LAN is configurable via `-s <subnet>` / `-m <mask>` (defaults `192.168.0.0` /
`255.255.255.0`, `src/streamguard.h:24-25`), parsed in `main()`'s `getopt`
loop into `lan_network` / `lan_netmask`. On a /23, `192.168.0.10` and
`192.168.1.10` both index slot 10: they share a counter, and a block would hit
whichever full IP was last written to `clients[idx].ip`.

Fix: **reject, do not re-architect.** After option parsing in `main()` and
before capture starts, verify `lan_netmask` equals `htonl(0xFFFFFF00)`; if
not, `log_error` a message that names the constraint and the consequence
("StreamGuard indexes clients by the last IP octet and supports /24 LANs
only; a wider mask would make two devices share one quota counter") and exit
non-zero. Keying clients by full IP is deliberately out of scope — the home
LAN is a /24 and the hash-map rewrite is not worth its risk here.

**The dashboard.** `scripts/web/app.py:281`:

```python
app.run(host='0.0.0.0', port=port, debug=False)
```

It serves an HTML table at `/` and JSON at `/api/clients` and
`/api/clients/<ip>` with no authentication (there are no POST/PUT/DELETE
routes — it is read-only, which is why this is a disclosure issue and not a
control issue). `port` already comes from the `PORT` env var; follow that
pattern.

Required behaviour:
- Default `host` to `127.0.0.1`.
- `STREAMGUARD_BIND` overrides the bind address.
- `STREAMGUARD_WEB_PASSWORD`, when set, enables HTTP Basic auth on every
  route (username `admin` unless `STREAMGUARD_WEB_USER` is set). Use Flask's
  own primitives — do **not** add a new dependency such as Flask-BasicAuth.
  Compare with `hmac.compare_digest`, not `==`.
- If the bind address is not a loopback address and no password is set, log a
  clear warning at startup that usage data is exposed unauthenticated.

Then update `scripts/streamguard-web.service` so the documented install stays
consistent: add the new environment variables (commented out with sane
defaults). The service file is **not** a Critical File, but
`scripts/openwrt/**` and all `*.md` are — do not touch those; `CLAUDE.md`
documents the old behaviour and will be updated by the coordinator.

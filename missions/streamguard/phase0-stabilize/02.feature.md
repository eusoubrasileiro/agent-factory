# Feature 02 — Atomic state writes · mission phase0-stabilize

## Intent

The state file is truncated before it is written, so a crash or power loss
mid-save leaves a corrupt file. On the next start the daemon then forgets
which clients are blocked at the router, orphaning those blocks permanently.
Make saves atomic and make an unparseable state file loud instead of silent.

## Scope — the ONLY files you may touch

- `src/state.c`
- `src/state.h`
- `test/unit/test_state.c`

## My assertions

- **A6**: a save interrupted before completion leaves the previous state file
  intact and parseable with its original counters.
- **A7**: a corrupt/unparseable state file is reported at WARN level and does
  not silently present as "zero clients blocked".

Both proven by `test/unit/test_state.c` via `make -C src test-unit`.

## Pre-assembled context

Current save (`src/state.c:44-51`) — `fopen(..., "w")` truncates immediately:

```c
char *json_str = cJSON_Print(root);
FILE *f = fopen(state_file_path, "w");
if (f) {
    fputs(json_str, f);
    fclose(f);
} else {
    log_warn("Could not save state to %s: %s", state_file_path, strerror(errno));
}
```

Replace with write-to-temp + `rename()` (atomic within one filesystem):
build `"<state_file_path>.tmp"`, `fopen(tmp, "w")`, `fputs`, `fflush`,
`fsync(fileno(f))`, `fclose`, then `rename(tmp, state_file_path)`. On **any**
failure in that chain, log a warning, `unlink` the temp file, and leave the
existing state file untouched. Never `rename()` after a short write — check
the return of `fputs`/`fflush`/`fsync`.

Current load (`src/state.c:85-91`) treats a parse failure as a shrug:

```c
cJSON *root = cJSON_Parse(json_str);
free(json_str);
if (!root) {
    log_warn("Could not parse state file");
    return;
}
```

The message is already WARN but says nothing about the consequence. Make it
explicit that blocked clients may now be orphaned at the router and name the
path, e.g. `log_warn("State file %s is corrupt — cannot parse. Blocked "
"clients may remain blocked at the router with no local record; inspect the "
"router's set manually.", state_file_path)`. Also handle `ftell` returning
`-1` (`src/state.c:72-76`) before `malloc(fsize + 1)`, and treat a zero-length
file as corrupt rather than as an empty valid state.

Signature stays `void state_save(struct client_info *clients, int max_clients,
const char *state_file_path, time_t *last_state_save)`. If you need the
outcome observable for the test, you may change it to return `int` (0 = ok)
and update the single caller `save_state()` at `src/streamguard.c:349-351` —
that file is otherwise out of scope, so keep the edit to that one line.

Testing the interrupted save without killing the process: make the failure
injectable. The simplest approach that keeps production code honest is to
point `state_file_path` at a path whose **temp** file cannot be created (e.g.
a directory that is read-only, or pre-create `<path>.tmp` as a directory so
`fopen` fails), then assert the original file still parses with its original
values. Use `mkdtemp()` for the fixture directory and clean it up.

`test/unit/test_state.c` already exists and exercises `state_save`/
`state_load` round-trips — read it first and extend it in the same style.
It uses the **Criterion** framework (`#include <criterion/criterion.h>`,
`TestSuite(state, .init = setup, .fini = teardown);`, `Test(state, name) { … }`
with `cr_assert` / `cr_assert_eq` / `cr_assert_not_null`), plus the helpers
from `streamguard_test.h` (`test_clear_clients`, `test_init_client`,
`test_get_client`, `test_client_in_use`, `test_set_state_file_path`). Do not
convert it to plain C. Struct fields you will need
(`src/streamguard.h:70-86`): `ip`, `streaming_seconds`, `last_reset_date[16]`,
`in_use`, `is_blocked`.

Do **not** add history, extra persisted fields, or a schema version — a later
mission owns those.

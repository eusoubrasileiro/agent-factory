# Feature 01 — Single quota engine · mission phase0-stabilize

## Intent

Per-client quotas are parsed from config and printed in logs, but the live
enforcement path compares against the **global** quota — so a client
configured for 30 minutes is actually blocked at the global value. Make the
per-client quota govern blocking, and delete the parallel dead engine so only
one quota implementation exists.

## Scope — the ONLY files you may touch

- `src/streamguard.c`
- `src/streamguard.h`
- `src/Makefile`
- `src/client_quota.c` (delete)
- `src/client_quota.h` (delete)
- `test/unit/test_quota_policy.c` (new)
- `test/Makefile`

## My assertions

- **A1**: a client with `quota_seconds = 10` blocks after 10 s of tracked
  traffic while the global quota is 3600; a client with `quota_seconds = 0`
  blocks at the global quota — proven by `test/unit/test_quota_policy.c` via
  `make -C src test-unit`.
- **A2**: `src/client_quota.{c,h}` no longer exist and no longer appear in
  `src/Makefile` — proven by `test -e` and `grep -c client_quota src/Makefile`.

## Pre-assembled context

`src/client_quota.c` contains `cq_check_session_timeouts()`, a per-client
quota engine that is **compiled but never called** — only its header is
included at `src/streamguard.c:41`. Confirm with
`grep -rn "cq_check_session_timeouts\|client_quota" src/`. Delete both files,
remove `client_quota.c` from `SRCS` and `client_quota.o` from `OBJS` in
`src/Makefile:29-30`, and remove the `#include "client_quota.h"`. Also check
`test/Makefile` for a `client_quota.o` reference and remove it.

The live engine is `check_session_timeouts()` in `src/streamguard.c:452-504`.
It has **two** quota comparisons, both against the global `daily_quota`:

```c
/* line 481 — after a session ends on inactivity */
if (clients[i].streaming_seconds >= daily_quota) {
    block_client(clients[i].ip);
}
...
/* line 490 — during an ACTIVE session */
uint64_t session_duration_sec = (now_ms - clients[i].session_start_ms) / 1000;
uint64_t effective_time = clients[i].streaming_seconds + session_duration_sec;
if (effective_time >= daily_quota) { ... block_client(clients[i].ip); }
```

The correct per-client expression already appears twice elsewhere in the file
(`block_client` at `src/streamguard.c:213-214`, `resync_blocked_clients` at
`:304-305`):

```c
uint64_t effective_quota = (clients[idx].quota_seconds > 0) ?
                           clients[idx].quota_seconds : daily_quota;
```

Extract that into one helper and use it at **every** site, including the two
log lines at `:473-476` and `:495-496` which currently print `daily_quota` in
the "total: X/Y sec" message (they must print the effective quota, otherwise
logs contradict enforcement):

```c
/* in src/streamguard.c, near get_client_profile (~line 163) */
STATIC uint64_t effective_quota_for(int idx) {
    return (clients[idx].quota_seconds > 0) ? clients[idx].quota_seconds
                                            : daily_quota;
}
```

Expose it for testing by adding `uint64_t effective_quota_for(int idx);` to
the `#ifdef TESTING` block in `src/streamguard.h:146-166`. Existing test
helpers you can reuse there: `test_init_client(idx, ip, seconds, date)`,
`test_get_client(idx, &ip, &seconds, &blocked)`, `test_clear_clients()`.
`daily_quota` is a macro-mapped field of the global context
(`struct streamguard_ctx.daily_quota`, `src/streamguard.h:112`).

Model the new test file on an existing one — read `test/unit/test_state.c`
for the harness shape (plain C `main()`, `assert`-style checks, registered in
`test/Makefile`'s unit binary list). Add `test_quota_policy` there the same
way the existing binaries are added.

Note: `clients[idx].quota_seconds` is populated from config by
`src/config.c`; you do **not** need to change config parsing.

# Feature 03 — Enforcer vtable + idempotent firewall ops · mission phase0-stabilize

## Intent

Firewall operations are not idempotent: `nft add element` on an element that
already exists, and `ipset add` without `-exist`, both exit non-zero. A code
comment wrongly claims duplicates are "silently ignored", so the retry logic
treats an already-applied block as a failure and retries it forever. Make the
operations idempotent, and route every external effect through a small vtable
so later features can inject failures in tests without a router.

## Scope — the ONLY files you may touch

- `src/firewall.c`
- `src/firewall.h`
- `test/unit/test_firewall.c` (new)
- `test/Makefile`

## My assertions

- **A5**: adding an element already present, or deleting one already absent,

## Pre-assembled context

Current implementation, `src/firewall.c:21-56` (complete):

```c
int firewall_execute(const struct firewall_config *cfg,
                     const char *action, const char *set_name, const char *ip_str) {
    char fw_cmd[256];
    char cmd[512];
    if (strcmp(cfg->fw_type, "ipset") == 0) {
        snprintf(fw_cmd, sizeof(fw_cmd), "ipset %s %s %s 2>/dev/null",
                 action, set_name, ip_str);
    } else {
        const char *nft_action = (strcmp(action, "add") == 0) ? "add" : "delete";
        snprintf(fw_cmd, sizeof(fw_cmd),
                 "nft %s element inet fw4 %s '{ %s }' 2>/dev/null",
                 nft_action, set_name, ip_str);
    }
    if (cfg->fw_router_ip != NULL) {
        if (cfg->fw_ssh_keyfile != NULL) {
            snprintf(cmd, sizeof(cmd),
                "ssh -o ConnectTimeout=5 -o BatchMode=yes -i %s %s@%s \"%s\"",
                cfg->fw_ssh_keyfile, cfg->fw_ssh_user, cfg->fw_router_ip, fw_cmd);
        } else { /* same without -i */ }
    } else {
        snprintf(cmd, sizeof(cmd), "%s", fw_cmd);
    }
    log_debug("Executing: %s", cmd);
    return system(cmd);
}
```

Two changes.

**1 — Idempotency.**
- ipset: append `-exist` to both add and del (`ipset add -exist …`,
  `ipset del -exist …`).
- nft has no `-exist` flag. Make add and delete self-checking in one SSH
  round-trip, e.g. for add:
  `nft get element inet fw4 SET '{ IP }' >/dev/null 2>&1 || nft add element inet fw4 SET '{ IP }'`
  and the mirror for delete (`nft get … >/dev/null 2>&1 && nft delete element … ; true`
  — the operation must exit 0 when the element is already absent).
  Mind the buffer sizes: `fw_cmd[256]` and `cmd[512]` are tight once the
  command doubles. Enlarge them and **check `snprintf` truncation** (compare
  the return against the buffer size) rather than silently emitting a
  malformed command.
- Fix the false comment at `src/firewall.c:64` ("Duplicates silently ignored
  by both nft and ipset") — it is wrong and caused this bug.

**2 — The vtable.** Add to `src/firewall.h`:

```c
struct enforcer_ops {
    int (*execute)(const struct firewall_config *cfg, const char *action,
                   const char *set_name, const char *ip_str);
};
extern const struct enforcer_ops firewall_real_ops;   /* wraps firewall_execute */
```

Keep `firewall_execute` exported and behaviour-identical for existing callers;
the vtable is an additional seam, not a rewrite. Feature 04 will call through
it and substitute a recording stub in tests.

**Testability of command construction.** `system()` cannot run in a unit test.
Split command *building* from *running*: a pure function

```c
/* returns 0 on success, -1 on truncation; writes the full shell command */
int firewall_build_command(const struct firewall_config *cfg, const char *action,
                           const char *set_name, const char *ip_str,
                           char *out, size_t out_len);
```

`firewall_execute` becomes build + `system()`. The unit test then asserts on
the built string (contains `-exist` for ipset; contains the `get … ||`/`&&`
guard for nft; no truncation for long inputs) without executing anything.

Security note, already true and to be preserved: `ip_str` always comes from
`inet_ntop()` on a `uint32_t`, so it can only ever be a dotted quad — no shell
metacharacters can reach `system()`. Do not weaken that by accepting
free-form strings.

Do **not** touch `firewall_add_destination` (`src/firewall.c:59-66`) beyond
fixing its comment — the destination-set mechanism is frozen and gets deleted
in a later mission.

# Feature 05 — Async firewall worker · mission phase0-stabilize

## Intent

Every newly detected streaming flow triggers a synchronous `system("ssh …")`
**inside the packet callback**. A full SSH handshake takes hundreds of
milliseconds while packets queue in the capture buffer, so heavy streaming
causes buffer overruns and dropped packets — silently under-counting the very
quota being enforced. Move all external firewall effects onto a single worker
thread and reuse one SSH connection.

## Pre-assembled context

The offending call chain: `packet_handler` (`src/streamguard.c:507-657`) calls
`add_streaming_destination` at line 617, which is:

```c
/* src/streamguard.c:200-205 */
static void add_streaming_destination(uint32_t dest_ip) {
    if (!enforce_mode || is_lan_ip(dest_ip)) return;
    execute_firewall_command("add", "streaming_destinations", ip_to_str(dest_ip));
}
```

`execute_firewall_command` (`:194-197`) → `firewall_execute` → `system()`.

Feature 04 also calls the enforcer from `reconcile_clients()`, which runs on
the maintenance tick (not the packet path) but still blocks the single main
thread on SSH. Both must go through the queue.

**Design (decided — implement exactly this shape).**

Single-producer/single-consumer bounded queue, one worker thread:

```c
enum op_kind { OP_BLOCK_ADD, OP_BLOCK_DEL, OP_DEST_ADD };
struct fw_op {
    enum op_kind kind;
    uint32_t     ip;        /* plain value — never a pointer into clients[] */
};
#define FW_QUEUE_SLOTS 128
```

Rules that matter:

- Ops carry **plain values only**. The worker must never touch `clients[]`,
  the flow table, or nDPI structures — those stay owned by the main thread.
  This is what keeps the daemon safe without locking everything.
- Shared state is exactly: the ring buffer, its head/tail, and a shutdown
  flag, all guarded by one `pthread_mutex_t` + one `pthread_cond_t`.
- **Coalescing**: if an op for the same `(kind-family, ip)` is already queued,
  replace it rather than appending — the latest desired state wins. Block and
  unblock for the same IP are the same family: a queued `OP_BLOCK_ADD`
  superseded by `OP_BLOCK_DEL` must become a single `OP_BLOCK_DEL`.
- **Queue-full policy**: drop the oldest `OP_DEST_ADD` to make room. Never
  drop `OP_BLOCK_ADD`/`OP_BLOCK_DEL` — those govern whether a family member
  has internet. If the queue is full of block ops, log a WARN and block the
  producer briefly rather than losing one.
- Shutdown: set the flag, signal the condvar, `pthread_join` the worker, then
  drain remaining block ops synchronously so a clean exit doesn't strand a
  pending unblock. Wire this into the existing shutdown path in `main()`.

**Result reporting back to reconcile.** Feature 04's reconcile loop needs the
success/failure of an op to update `actual_block` and backoff. Do **not** have
the worker write `clients[]`. Instead give the worker a small completion ring
(same mutex) holding `{ip, kind, ret}`, and drain it at the top of the
maintenance tick, applying results on the main thread. Reconcile then treats
"op in flight" as a third state: do not re-enqueue an op for a client that
already has one outstanding — track a per-client `op_inflight` flag, cleared
when its completion is drained.

**SSH connection reuse** (`src/firewall.c`, the SSH wrapping at `:40-49`):
add to both `ssh` invocations
`-o ControlMaster=auto -o ControlPath=/run/streamguard/ssh-%r@%h -o ControlPersist=60`
keeping the existing `-o ConnectTimeout=5 -o BatchMode=yes`. The directory is
provided by systemd (`RuntimeDirectory=streamguard`); if it does not exist,
fall back to no ControlPath rather than failing — check with `access()` at
startup once, not per command. Mind the `cmd[512]` buffer (Feature 03 may have
already enlarged it) and keep the truncation check.

Link `-lpthread`: `src/Makefile:9` already lists `-lpthread` inside
`NDPI_LIBS` for the local-nDPI branch; confirm it is present for the
pkg-config branch too and add it to `LDFLAGS` if not.

**Do not** extend, batch, or optimise the `streaming_destinations` mechanism
beyond moving it onto the queue — it is deleted in a later mission because
destination-IP blocking once took down a Google Meet call.

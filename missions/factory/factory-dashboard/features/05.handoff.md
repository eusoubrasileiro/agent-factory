# Feature 05 — Render PRD markdown bold in the dashboard — Handoff

**Status:** completed
**Commit:** `<TBD> feat(factory): render PRD markdown bold in dashboard (factory-dashboard 05)`

## What landed
- `scripts/factory/board-report.mjs`
  - New exported helper `renderInline(text)` next to the existing `esc()`. It
    HTML-escapes FIRST (reusing `esc()`), then rewrites paired `**...**` segments
    in the escaped string to `<strong>...</strong>` via the non-greedy regex
    `/\*\*(.+?)\*\*/g`. Unpaired/odd-count `**` is left as escaped text (regex
    can't match it), so no dangling opener can ever be emitted.
  - The renderer's `recurso` cell now calls `renderInline(r.recurso)` instead of
    `esc(r.recurso)`. Every other interpolation (id, risco, status, mission slug,
    branch name, dates, chips, verdict) is untouched — bold processing is scoped
    to `recurso` only, as the spec demands.
- `scripts/factory/board-report.test.mjs` — 8 new tests covering `renderInline`
  in isolation (paired, escape-before-bold ordering, unpaired, multiple pairs,
  nullish hygiene, function-export smoke) plus two full-render tests proving
  (a) `recurso` carries `<strong>` with no literal `**` in the rendered DOM, and
  (b) `renderInline` is NOT applied to mission slugs (a `**weird**` slug stays
  escaped, never becomes bold).

## Security reasoning (for the validator)
Because `esc()` runs before the regex, file content can never introduce tag names
or attributes — the only HTML tags `renderInline` can possibly emit are the
literal `<strong>` and `</strong>` tokens it splices in itself. The regex runs on
already-escaped text, where `<` `>` `&` `"` `'` are all entities, so a hostile
`recurso` like `<script>` arrives at the regex as `&lt;script&gt;` and is
untouched by the bold rewrite. There is no double-escape: the inserted `<strong>`
tokens are added after `esc()` returns.

## Notes for the validator
- The `recurso` cells in the live `docs/prd/nexus-build-backlog.md` (18 rows)
  carry shapes like `**Timer da janela WABA de 24h** — o BFF expõe ...` — all
  start with a single paired bold segment followed by an em-dash and prose.
  `renderInline` handles that case and any number of additional paired segments;
  stray single `**` in prose would survive as escaped text (safe).
- `renderInline` is exported from `board-report.mjs`. If a future worker needs
  inline-code (` `code` `) rendering, the spec's optional one-liner can be added
  as a second `.replace()` step in the same function — same escape-first rule.

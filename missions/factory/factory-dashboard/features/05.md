# Feature 05 — Render PRD markdown bold in the dashboard

> Small polish. TDD. When done: gate, commit, write `features/05.handoff.md`.

## Problem
Requirement `recurso` cells in `docs/prd/nexus-build-backlog.md` contain markdown
bold like `**Timer da janela WABA de 24h** — o BFF expõe ...`. The dashboard renders
the `**` literally instead of as bold, which looks unpolished.

## Deliverable
In `scripts/factory/board-report.mjs`, add a tiny helper (e.g. `renderInline(text)`)
used ONLY for the requirement `recurso` field in the HTML renderer:
1. HTML-escape the raw text FIRST (reuse the existing escape function — do not
   double-escape).
2. THEN convert paired `**...**` in the escaped string to `<strong>...</strong>`
   (regex `/\*\*(.+?)\*\*/g`, non-greedy). Also strip stray single-token `` `code` ``
   backticks to plain text if trivial — OPTIONAL, only if it's a one-liner; bold is
   the required part.
3. Unpaired/leftover `**` (odd count) must remain safely escaped text, never break
   the markup.

Security: because escape runs first, the only HTML introduced is the literal
`<strong>`/`</strong>` tags you insert — no user/file content can inject tags.

Apply it ONLY to `recurso`. Do NOT markdown-process mission slugs, IDs, or status.

## Tests (extend `scripts/factory/board-report.test.mjs`)
- `renderInline("**Foo** bar")` → `<strong>Foo</strong> bar`.
- `renderInline("a <b> & \"c\" **x**")` → escaped angle/amp/quote AND `<strong>x</strong>`
  (proves escape-before-bold ordering and no XSS).
- Unpaired: `renderInline("**oops")` → contains no `<strong>` and the `**` stays as
  escaped/plain text (no thrown error, no dangling tag).
- Full render: a fixture requirement whose recurso is `**Feature X**` produces
  `<strong>Feature X</strong>` in the HTML and NO literal `**`.

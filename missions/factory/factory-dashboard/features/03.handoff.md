**Status:** completed

## What I built

The publish + deploy half of the factory-dashboard mission. Three artifacts
that take the rendered `dist/factory-board/index.html` (produced by feature 02)
and ship it to the VPS as a Traefik-fronted, Basic-Auth-protected static site:

1. **`scripts/factory/board-publish.sh`** — bash, `set -euo pipefail`. Preflight
   on `dist/factory-board/index.html` (must be a file), then rsync to the VPS.
   The `--dry-run` path is provably offline: it constructs the rsync argv and
   echoes it without spawning ssh or rsync. Env overrides `PUBLISH_HOST`
   (default `deploy-host`) and `PUBLISH_DIR` (default
   `/opt/app/factory/public/scrumban/`).
2. **`deploy/factory-board/docker-compose.yml`** — `nginx:alpine` serving
   `./public` read-only, on the shared `network_public` external network, with
   the full Traefik v2 label set (Host rule, websecure entrypoint, ACME via
   `myresolver`, basicauth middleware, port 80). `${FACTORY_BASICAUTH}` stays
   a variable — no hash is ever committed.
3. **`deploy/factory-board/DEPLOY-VPS.md`** — operator runbook: Cloudflare
   A-record (DNS-only/gray), three-user htpasswd generation with the `$$`
   escape rule explained, `/opt/app/factory/.env` placement, compose
   bring-up, recurring `pnpm board:report && pnpm board:publish` flow
   (bind mount ⇒ no restart), troubleshooting matrix.

Plus the two root `package.json` scripts (`board:report`, `board:publish`) and
the `deploy/factory-board/.env` entry in `.gitignore`.

### The dry-run-is-offline guarantee

The three dry-run tests run `bash board-publish.sh --dry-run` with `PUBLISH_HOST=testhost`
and CWD pointed at a tmp fixture. The script reaches the dry-run branch only
after preflight succeeds, then echoes the constructed argv and exits 0 — no
`exec`, no `ssh`, no `rsync`. The tests assert the printed line matches
`rsync -az --delete` and `testhost:`, which proves the command was built
correctly without invoking it. There is no code path in the script that can
reach ssh/rsync when `$1 == --dry-run`.

## Design notes / decisions

### 1. Dry-run prints the rsync argv as `[dry-run] <cmd>`, not the bare cmd

A bare `rsync -az ...` echoed to stdout could be confused with the real run if
someone pipes the output to `bash`. The `[dry-run]` prefix makes it visually
unmistakable. The tests still match `rsync -az --delete` and `testhost:` —
they don't care about the prefix.

### 2. The rsync argv is built as a bash array, not a string

`RSYNC_CMD=(rsync -az --delete "$DIST_DIR" "${HOST}:${REMOTE_DIR}")` keeps
quoting correct even if `REMOTE_DIR` ends up containing spaces (it won't for
the canonical path, but env overrides are user input). For dry-run we print
`${RSYNC_CMD[*]}` (space-joined); for the real run we execute
`${RSYNC_CMD[@]}` (element-split).

### 3. `${1:-}` instead of `$1` — `set -u` safety

`set -u` would make `$1` fail when no arg is passed (which is the real-publish
case). `${1:-}` defaults to empty and lets the `== "--dry-run"` check evaluate
cleanly to false. This is the standard bash idiom.

### 4. Compose: `network_public` is `external: true`

The factory board shares Traefik + ACME + the public network with the other
AmiticIA services already on the VPS. Bringing up `network_public` is NOT this
compose file's job — the runbook notes that the operator must ensure it exists
(via the stack that owns it). Trying to declare it as a local bridge would
create a second, isolated network and Traefik wouldn't see the container.

### 5. The `$$` escape for htpasswd — Compose + Traefik, double layer

`docker compose config` will show `$$$$` in the rendered label because Compose
performs `$$` → `$` on the variable value AND on YAML literals. At runtime,
Traefik reads the label after Compose has done its single escape pass, so the
final htpasswd string the auth middleware parses contains single `$`. The
runbook spells out: in `/opt/app/factory/.env`, write `andre:$$apr1$$xyz$$abc...`
— i.e. double every `$` from the raw `htpasswd -nb` output. This is the
canonical Traefik+Compose pattern documented at
https://doc.traefik.io/traefik/middlewares/http/basicauth/. If you see 401s
that reject every password, this is the place to look first.

### 6. Bind mount, not `volumes:` from a named volume

`./public:/usr/share/nginx/html:ro` is a bind mount on purpose. The recurring
`board:publish` rsync writes into `/opt/app/factory/public/scrumban/`,
which is `./public/scrumban/` relative to the compose file. The container
sees the new `index.html` immediately via the bind mount — no `docker compose
restart`, no `docker compose up --force-recreate`. This is what makes
`pnpm board:report && pnpm board:publish` a sub-second operation.

## Things worker 04 (backfill + docs + integration) must know

1. **The end-to-end pipeline is now wired.** From the repo root:
   ```bash
   pnpm board:report    # renders dist/factory-board/index.html
   pnpm board:publish   # rsync to deploy-host:/opt/app/factory/public/scrumban/
   ```
   Both scripts are in `package.json` and the pre-commit hook passed with them.

2. **`pnpm board:publish` is gate-free by design.** The pre-commit hook does
   NOT block commits if the dist is missing — the gate is at publish time, in
   the script itself (exit 1 with a hint to run `pnpm board:report`). This is
   the right place: the gate is about the operator's workflow, not about the
   code being committed. Don't try to add a pre-commit gate for this.

3. **The deploy dir is `deploy/factory-board/` (singular, not `deploys/`).**
   It is parallel to the eventual `deploy/backend/`, `deploy/frontend/` etc.
   if those ever materialize. The compose file is at
   `deploy/factory-board/docker-compose.yml` — keep that path stable.

4. **The `.env` for the compose file lives at
   `/opt/app/factory/.env` on the VPS** (NOT in the repo, NOT at
   `deploy/factory-board/.env` — that path is gitignored but unused). The
   runbook uses `docker compose -f docker-compose.yml --env-file .env` to
   make the variable available. If you change the path, update the runbook.

5. **The `network_public` Traefik network is shared.** Any future AmiticIA
   service that wants Traefik routing should reuse it — don't create a new
   network per service.

6. **The dry-run path is the contract surface for offline validation.** If
   feature 04 wants to add a CI step or a quality-gate check, it can call
   `bash scripts/factory/board-publish.sh --dry-run` and grep the output for
   `rsync -az --delete`. No fixture setup needed beyond a tmp `dist/factory-board/index.html`.
   The test file shows the pattern.

7. **`PUBLISH_DIR` has a trailing slash by spec.** rsync's source-vs-dest
   behavior is slash-sensitive: `dist/factory-board/` (with slash) means
   "contents of", so files land directly in `PUBLISH_DIR`, not in a nested
   `factory-board/` subdir. If you ever want to change the destination
   layout, change both `DIST_DIR` and `REMOTE_DIR` together.

8. **The board URL is `https://factory.example.com/scrumban/` (note the
   trailing slash).** The `scrumban/` subdir comes from `PUBLISH_DIR`. nginx
   serves the bind-mounted root, so a request to `/scrumban/` resolves to
   `./public/scrumban/index.html` automatically. A request to
   `https://factory.example.com/` (no scrumban/) would 404 — that's by
   design, leaving the root for future AmiticIA factory pages.

9. **`FACTORY_BASICAUTH` has three users: andre, tenant-a, operator.** These are
   the only people who should ever see the board. The runbook generates them
   one-by-one with `htpasswd -nb` and joins with commas.

10. **The compose file is validation-tested.** `docker compose config` passes
    locally (Docker 29.6.1). The validator machine should re-run the test
    from `board-publish.test.mjs` — it auto-skips with a clear note if docker
    is missing.

## unmet_knowledge[]

- **Does Andre want a recurring auto-publish hook (post-commit on the
  mission-applied branch, or a cron on the VPS that pulls + renders)?** The
  spec didn't say; I assumed manual (`pnpm board:report && pnpm board:publish`
  on demand). Feature 02's handoff raised the same question for the render
  step; this handoff raises it for the publish step. Together they're a
  single decision: is the board operator-triggered, or continuous?
- **Is the Cloudflare A-record DNS-only (gray) or proxied (orange)?** I
  assumed DNS-only because Traefik does its own ACME and orange-clouding
  would mask the origin. If AmiticIA already has a Cloudflare-proxied
  pattern that coexists with Traefik (e.g. via a `CLOUDFLARE_API_TOKEN` env
  for DNS-01 challenges), the runbook's gray-cloud instruction needs to
  change. Andre should ratify.
- **VPS host identity: is `deploy-host` the canonical SSH alias, or should it
  be `amiticia-vps` / `factory-vps`?** The spec default is `deploy-host`, which
  is the SSH alias in Andre's `~/.ssh/config`. If the alias is different on
  other workstations, operators will need to override `PUBLISH_HOST`. The
  runbook assumes the alias is already configured and doesn't tell operators
  how to set it up.
- **Does the `/opt/app/factory/public/scrumban/` path exist on the VPS,
  or does it need to be created by the runbook's `mkdir -p`?** I included the
  `mkdir -p` defensively. If the VPS already has `/opt/app/factory/`
  from another service, the runbook is redundant but harmless.

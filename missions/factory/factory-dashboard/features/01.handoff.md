## What I built

A pure, read-only model layer (`scripts/factory/board-report.mjs`) that joins the
PRD backlog rows → mission dirs → git branches into one serializable object. No
HTML, no writes, no side effects (the only effect is `collectGitInfo`, which only
runs read-only git commands).

## Exported function signatures

```ts
// scripts/factory/board-report.mjs

parseRequirementsLine(briefMarkdown: string | null | undefined): string[] | null
//  Scans for `**Requirements:** <value>` (case-insensitive key, tolerates a
//  leading `>` blockquote marker and any leading whitespace). Returns null when
//  no line is present; [] for `none`; otherwise the comma-separated backlog IDs
//  that match /^[A-D]\d+$/. Invalid tokens are silently skipped, never thrown.

collectGitInfo(repoRoot: string): {
  branches: Array<{
    name: string;            // "agent/<slug>"
    slug: string;            // name without the "agent/" prefix
    merged: boolean;         // `git merge-base --is-ancestor <branch> main` exit 0
    lastCommitISO: string | null;  // `git log -1 --format=%cI <branch>` or null
  }>
}
//  Missing git / not-a-repo / no agent/* branches → { branches: [] }. Never throws.

buildTraceabilityModel({
  missionsDir: string,       // factory/missions (or override)
  prdPath: string,           // docs/prd/nexus-build-backlog.md (or override)
  gitInfo: { branches: [...] },  // INJECTED — pass collectGitInfo(repoRoot) here
}): {
  generatedAt: string;       // new Date().toISOString()
  requirements: Array<{
    id: string;              // PRD row id (A1..D3)
    recurso: string;
    risco: string;
    situacao: string;        // raw PRD cell text
    missionSlug: string | null;  // first mission whose brief declares this id
    liveStatus: string;      // linked mission's derived status, OR normalizeSituacao(situacao).status
  }>;
  missions: Array<{
    slug: string;
    status: string;          // from deriveMissionState(dir)
    gateReason: string | null;
    requirements: string[] | null;  // from parseRequirementsLine(brief.md); null = no brief
    features: number;        // count of features/NN.md (excludes *.handoff.md)
    handoffs: number;        // count of features/NN.handoff.md
    lastVerdict: { verdict: "PASS" | "FAIL", round: number } | null;  // last valid JSONL line
    branch: { name, slug, merged, lastCommitISO } | null;  // matched by slug; null if no branch
  }>;
  orphanBranches: Array<{ name, slug, merged, lastCommitISO }>;  // git branches with no mission dir
}
```

The CLI (`node scripts/factory/board-report.mjs`) prints the model as pretty
JSON. Flags: `--missions <dir>`, `--prd <path>`, `--repo <root>`.

## Things worker 02 (HTML renderer) must know

1. **Import the model, don't re-derive.** `buildTraceabilityModel` is the only
   entry point you need:
   ```js
   import { buildTraceabilityModel, collectGitInfo } from "./board-report.mjs";
   const model = buildTraceabilityModel({
     missionsDir, prdPath,
     gitInfo: collectGitInfo(repoRoot),
   });
   ```
2. **All UI text must be Portuguese** (per AGENTS.md). The model carries the raw
   PRD `recurso` / `risco` / `situacao` strings verbatim — render them as-is.
3. **The model is plain JSON-serializable** (no functions, no Dates —
   `generatedAt` is already an ISO string). You can `JSON.stringify` it straight
   into the page or pass it through any template.
4. **Three natural views fall out of the shape:**
   - *Requisitos* — iterate `model.requirements`. `missionSlug` null = unmapped;
     `liveStatus` is the display status (mission-derived when mapped, PRD-derived
     otherwise).
   - *Missões* — iterate `model.missions`. `gateReason` is non-null when the
     mission is waiting on Andre (`gate:ratify` | `gate:escalated` |
     `gate:approve-plan`) — surface this prominently.
   - *Drill-down* — `slug` joins a mission to its `requirements[]` (the backlog
     IDs it claims) and its `branch` (the live `agent/<slug>` ref).
5. **`orphanBranches`** are agent branches with no mission dir — useful as a
   "needs cleanup" panel. A branch with `merged: true` was merged into `main`.
6. **`lastVerdict` shape** is `{ verdict, round }` (lowercase keys) or `null`.
   Render the round count when you surface a FAIL.
7. **Don't expect a 1:1 requirements↔missions cardinality.** A mission may claim
   multiple ids; an id maps to **the first** mission (in alphabetical slug order)
   whose brief declares it. Unmapped PRD rows still appear in `requirements[]`
   with `missionSlug: null` — they are not dropped.
8. **The `**Requirements:**` line lives ONLY in `brief.md`.** Never scan
   `contract.md` / `plan.md` for ids — their local labels (e.g. a mission's
   `C1`/`C2` acceptance criteria) would collide with backlog ids. The collision
   guard test (`COLLISION GUARD: ...`) locks this down — keep it that way.
9. **No side effects from the model layer** — it never writes, never spawns git
   other than read-only `collectGitInfo`. You can call it from a build script,
   a watch loop, or a server without surprises.

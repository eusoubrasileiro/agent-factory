# Feature 05 — Profile conformance suite (the enforcement)

## Goal

Genericity that is not enforced rots on the first deadline. This feature adds the
test that **fails loudly** the moment (a) a project profile is malformed, or (b) a
product literal creeps back into the engine.

Depends on Features 02 (`resolveProject().profile`) and 03 (`criticalFileRules`,
`renderCageSettings(…, {criticalFiles})`). Both are already merged into this branch.

## Files you may touch (ONLY these)

- CREATE `scripts/project-profile.test.mjs`

Nothing else. If a profile on disk fails your new suite, **do not fix the profile** —
report it in the handoff. A red test here is a real finding.

## TDD

This feature IS tests. Write them, run them, make them pass without touching
non-test code. Use `node:test` + `node:assert/strict`. **Not vitest.**

## Part 1 — per-profile conformance (iterate, do not hardcode)

Discover profiles by reading the directory `projects/` at the factory root
(`path.resolve(path.dirname(fileURLToPath(import.meta.url)), "..")`). For EVERY
subdirectory that contains a `project.json`, generate this set of tests. Use a loop
plus `test()` inside it so each profile gets its own named tests — the name MUST
carry the profile id so a failure says *which* project broke:

1. `` `profile ${id}: required files present (project.json, critical-files.json)` ``
2. `` `profile ${id}: project.json declares id matching its directory name` ``
3. `` `profile ${id}: gate[] is a non-empty array of non-empty strings` ``
4. `` `profile ${id}: critical-files.json is an array of non-empty repo-relative globs` ``
   — reject a leading `/` or a `..` segment.
5. `` `profile ${id}: critical files render through cage-settings with a clean audit` ``
   — render with `renderCageSettings(loadTemplate(), "/tmp/x", {criticalFiles})`
   then assert `auditCageSettings(rendered)` returns `[]`, and assert every glob
   appears as BOTH an `Edit(//…)` and a `Write(//…)` rule.
6. `` `profile ${id}: seat.env, when present, parses to KEY=value and carries no real-looking secret` ``
   — skip (`t.skip()`) when the file is absent (the `factory` profile has none).
   Reuse `parseEnv` / `extractSecrets` exported from `./probe-secrets.mjs` rather
   than writing a new parser. Assert: no `eyJ…` JWT shape, no `sk-…`, no `AIza…`,
   and no `DATABASE_URL`/`DIRECT_URL` key (dispatch appends those per-agent).
7. `` `profile ${id}: path resolves to an existing checkout` ``
   — `t.skip()` when the resolved `repoRoot` does not exist, so the suite stays
   green on a machine that has the factory checkout but not every product.
8. `` `profile ${id}: resolveProject({project: id}) round-trips the profile` ``
   — the returned `profile.gate` / `profile.criticalFiles` equal the on-disk JSON,
   and `seatEnvPath`/`validationPath` are absolute-or-null.

Guard: if `projects/` contains **zero** profiles, that is itself a failure
(`test("projects/ contains at least one profile")`) — an empty loop must never
masquerade as a green suite.

## Part 2 — the meta test: the engine carries no product literals

`test("engine sources carry no product literals")`

Scan these paths at the factory root:
- `scripts/*.mjs` **excluding** `*.test.mjs`
- `scripts/lib/*.mjs`
- `templates/*`
- `skills/*/SKILL.md`

Assert none of them contains a product id. Derive the forbidden ids from the
profiles themselves — every profile id EXCEPT `factory` (the engine's own dogfood
profile legitimately names itself). Do **not** hardcode the string `wahub` in the
assertion; read `projects/` and build the list. Report every offending
`file:line` in the assertion message so the failure is actionable.

**Why test files are exempt** (state this in a comment): engine tests may use a
real profile id as an opaque fixture, and profiles are checked into this repo. The
architectural rule is that *shipping engine code* never names a product; the
conformance suite in Part 1 is what pins each product's actual facts. Exempting
tests keeps the rule enforceable instead of aspirational.

## Part 3 — the moved assertion (do not lose coverage)

Feature 03 removed `"the shipped template denies every wahub Critical File"` from
`scripts/cage-settings.test.mjs`. Its coverage must live on **generically** in
Part 1 test 5: for every profile, every declared critical glob becomes an Edit and
a Write deny rule. Confirm in your handoff that the wahub profile's 12 globs are
covered by that test at runtime.

## Conventions

Plain Node ESM `.mjs`, no deps beyond `node:*`. No network, no writes outside
`mkdtempSync(path.join(tmpdir(), …))`, always cleaned up in a `finally`.

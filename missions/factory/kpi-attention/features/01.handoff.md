## Design decisions (ambiguities I resolved; documented in the headers too)

1. **B2 source = metrics.jsonl via `seatTokens`, not stats.json.** stats.json can
   lag or be fail-open zero; metrics.jsonl is the live instrument. A seat's tokens
   are "measured" only if ≥1 phase_end carries a numeric token field — otherwise
   `null` (the E1-d fix: a phase_end with no token fields is absence, not zero).
2. **B4 denominator (`features`) = merged-mission count.** A merged mission is a
   delivered feature, and it is the only window-bounded feature count available
   (dossier `features/NN.md` writeups are not window-bounded). The pure `buildKpi`
   takes `features` as an injected input regardless, so the math is pinned by tests.
3. **B3 is factory-global.** The Opus coordinator runs in the factory repo, not
   per-project, so its transcript tokens can't yet be attributed per-project.
   v1 puts the factory-wide coordinator total on each project row; per-project
   attribution needs the F4 session-tag join, which is the **coordinator's** seat.
4. **Windowing.** B1 is bounded by `git --since`; B2/B4 by event `ts`; B3 by
   transcript-row `timestamp`. Default window 30d (`--window <days>`).

## ⚠️ Escalations (honest — read before merging)

1. **I could NOT run `pnpm test` from inside this cage.** The seat's permission
   layer denies all interpreter execution (`node …`, `pnpm test`) and write-git
   (`git add`/`git commit`); only the Read/Edit/Write tools and read-only shell
   pass. The `cage-bash-hook` itself *allows* `pnpm test`, but the session's
   `acceptEdits` mode does not auto-accept Bash, so every gate invocation
   returned "requires approval" and was not approvable from the seat. **The
   coordinator must run `pnpm test` from the worktree root before committing.**
   I traced every assertion above statically against the implementation (arithmetic,
   export/import surface, product-literal scan, windowing, the two mutation gates)
   and found them consistent — but tracing is not execution. Treat green as
   unconfirmed until the coordinator runs it.

2. **I did NOT commit.** Discipline forbids a commit before a green gate, and
   `git add`/`commit` are gated anyway. Files are written to the worktree on
   `agent/kpi-attention`; the coordinator stages + commits once `pnpm test` is
   green (suggested message: `feat(factory): kpi-attention — session-cost + kpi
   readout (plan-A F4+F5)`).

3. **The two riskiest tests** (most dependent on real-tool behaviour, not pure
   logic) are the CLI smoke tests that `spawnSync` a real tiny git repo with a
   `--no-ff` merge. They mirror the proven `initGitRepoWithBranch` pattern in
   `mission-stats.test.mjs`; if `git log --merges --grep <slug>` doesn't match
   the merge subject on some git version, `countMergedMissions`'s pure logic has
   dedicated injected-runner tests that will still hold.

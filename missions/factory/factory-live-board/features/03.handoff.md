## unmet_knowledge

- **`stripTimestampLines` must strip `última atualização` too (THREE markers now).** The
  root index emits a per-card `<span class="card-updated">última atualização <iso></span>`
  that mirrors each project dashboard's `generatedAt`. Since board-report regenerates
  `generatedAt = new Date().toISOString()` on every render, this field is volatile across
  identical-state runs. My first GREEN run caught it: two identical-state runs produced
  different hashes and the second run reported "publicado" instead of "sem mudanças". Fix:
  add `!line.includes("última atualização")` to the filter in `stripTimestampLines`. This
  is the same class of bug W2 hit with `"generatedAt"` — the rule is: **every volatile
  timestamp in any rendered HTML must be in `stripTimestampLines` or the hash guard
  breaks.** If W4 adds timestamp fields to the Histórico tab, add them here too.
- **`board-publish.test.mjs` was NOT in the dispatcher's explicit scope list**, but the
  gate (`pnpm test:factory`) forced a 1-line fix: the existing test at line 67 asserted
  the default `REMOTE_DIR` was `/opt/app/factory/public/scrumban/`. After repointing
  `board-publish.sh` to `public/` (spec deliverable 5), that assertion broke. The fix is
  minimal — just the expected-path regex (now `public/` without `scrumban/`, plus an
  explicit `doesNotMatch` on the old path). This is mechanically coupled to the
  board-publish.sh change; leaving it broken would violate the gate rule.
- **The compose file's header comment (line 9) is now stale** — it references
  `/opt/app/factory/public/scrumban/`. The spec's Do NOT forbids changing the
  compose file ("layout change is server-side content only"), so I left it. The actual
  compose config (`./public:/usr/share/nginx/html:ro`) is correct and unchanged — nginx
  serves the `public/` root, so `/scrumban/` resolves to the redirect file and `/`
  resolves to the root index. Feature 05 (integration) may want to refresh that comment.
- **`factory/history.jsonl` (50 lines) exists in the worktree but is NOT my commit.** It
  was generated by a real autopublish run (orchestrator or prior worker). My tests use
  tmp dirs (`--repo <tmp>`), so they never touched the real file. I did not commit it —
  it's test/orchestration output, not a feature-03 deliverable.

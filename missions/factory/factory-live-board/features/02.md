# Feature 02 — Autopublish funnel + bindings

> Worker contract: TDD. House style = `scripts/factory/board-sync.mjs`. When done:
> `pnpm test:factory`, `pnpm lint`, commit, write
> `factory/missions/factory-live-board/features/02.handoff.md`.

## Deliverables

1. NEW `scripts/factory/board-autopublish.mjs` — the ONE idempotent funnel:
   - Reads `deploy/factory-board/projects.json` (missing → soft log + exit 0).
   - For each project entry: spawn `board-report.mjs` with `--missions/--prd/--repo/--out
     dist/factory-board/<id>/index.html` (paths resolved from entry.repo). For now the
     manifest has only wahub; the loop must still be generic.
   - Root index + /scrumban/ redirect come in feature 03 — for THIS feature emit only
     per-project pages; leave a `renderRootIndex` stub call site.
   - Content hash: sha256 over the concatenated rendered HTML files with any line
     containing `gerado em` stripped. Memo file `dist/factory-board/.hash`. Unchanged →
     log "sem mudanças" to `factory/.publish.log` and exit 0 (NO history append, NO rsync).
   - Changed: invoke `board-publish.sh` (rsync), then append history snapshots via the
     feature-04 module — until feature 04 lands, write the snapshot rows inline with the
     shape fixed in plan.md (feature 04 will extract).
   - `--dry-run`: full render + hash logic, print the rsync command, NO network, NO
     rsync execution. Exit 0.
   - Every failure path: log one line to `factory/.publish.log` and exit 0 (binding
     context must never break). `--strict` flag flips to exit 1 for CI/debug.
   - HARD INVARIANT (contract A3): this script never executes git write commands
     (commit/add/push/merge). Read-only git (branch listing inside board-report) is fine.

2. Bindings:
   - `verdict.mjs` + `ratify.mjs`: after autoCommit, spawn autopublish DETACHED
     (`spawn(process.execPath, [path], {detached:true, stdio:"ignore"}).unref()`),
     wrapped in try/catch (same soft-fail philosophy as syncBoard).
   - `.husky/post-commit`: append `(node scripts/factory/board-autopublish.mjs >/dev/null 2>&1 &)`.
   - NEW `.husky/post-merge`: same line (plus the standard husky shebang/header copied
     from post-commit).

3. Loop safety is by construction: autopublish makes no commits → post-commit cannot
   re-fire it; double-fire (verdict autoCommit → post-commit) is absorbed by the hash
   guard. Document this in a JSDoc header.

## Tests — NEW `scripts/factory/board-autopublish.test.mjs` (node:test, tmp fixtures)
- dry-run exits 0 offline, prints rsync target `deploy-host:/opt/app/factory/public/`.
- Hash guard: two consecutive runs on identical fixture state → second logs "sem
  mudanças", history.jsonl unchanged; touch a marker file → new snapshot rows appear.
- `gerado em` timestamp difference alone does NOT change the hash.
- Missing projects.json → exit 0, one log line.
- Source-level assertion: file content has no `git commit`/`git add`/`git push` strings
  (cheap A3 proof).

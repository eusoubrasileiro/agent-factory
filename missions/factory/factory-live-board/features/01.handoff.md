## notes for W2 (board-autopublish.mjs)

- **`autoCommit` is your reuse point, not a thing to re-implement.** Import from
  `./git-autocommit.mjs`: `import { autoCommit } from "./git-autocommit.mjs"`. Signature:
  `autoCommit(missionsRoot, slug, message)` where `missionsRoot` is the `--dir` value
  (i.e. `factory/missions`), `slug` is the mission slug, `message` is the FULL commit
  message already prefixed `chore(factory): …`. It derives `repoRoot =
  path.resolve(missionsRoot, "..", "..")`.
- **But per plan.md fixed decision, `board-autopublish.mjs` itself is git-write-free.**
  You do NOT call `autoCommit` from inside the autopublish funnel. The autopublish
  bindings you add go into the **post-commit / post-merge hooks** (fire-and-forget
  `node scripts/factory/board-autopublish.mjs`), which run AFTER a commit lands —
  including the verdict/ratify auto-commits this feature now produces. The loop is
  bounded because autopublish makes no commits (plan.md loop-termination decision).
- **autoCommit commits `factory/missions/<slug>` + `factory/history.jsonl`.** The
  `history.jsonl` pathspec is filtered to existing-on-disk paths, so it is silently
  absent until feature 04 starts writing it — no action needed from you.
- **Commit message convention is `chore(factory): <verb> <slug> …`.** Match this for any
  new autoCommit call sites so the pre-commit fast-path recognises them as docs-only.
- **The fast-path guard makes these commits cheap** (~30 ms, skips the full gate). Any
  commit whose staged set is entirely under `factory/missions/` + `factory/history.jsonl`
  is docs-only. If autopublish ever needs to commit something outside that set, the full
  gate will run — design accordingly.
- **`ts` is now on every verdict record** (`validate.log` lines). Feature 04's
  history/velocity metrics can rely on `record.ts` as the per-round timestamp.

## unmet_knowledge

- **The `.husky/pre-commit` gate has no `set -e`** — only the LAST command's exit code
  (`pnpm --filter @wahub/frontend test`) decides the gate result. Discovered while
  testing the guard: a bare fixture's gate no-ops to 0 because the trailing `--filter`
  matches nothing. My guard tests use a sentinel `package.json` (`name:
  "@wahub/frontend"`, `test` exits 1) to make the full gate observable. Future hook
  edits should be aware only the final line is load-bearing.
- **`git add -A -- <pathspec>` exits 128 (fatal) when ANY pathspec matches nothing on
  disk**, even if another pathspec in the same invocation does match. `autoCommit`
  filters its pathspec list to paths that exist on disk before calling git — W2 should
  do the same if it ever stages optional files.
- **`verdict-hook.test.mjs` copies `verdict.mjs` into an isolated temp dir to test
  board-sync-absent robustness.** It now also copies `git-autocommit.mjs` (verdict's new
  static import). If you add another static import to `verdict.mjs` (or `ratify.mjs`,
  if a parallel isolation test is ever added), extend the fixture's `cpSync` list.

## the quality-gate coverage prerequisite (fix-the-cause, not a re-baseline)

`pnpm quality-gate` **FAILED on first run** — 8 blocking regressions, all
coverage metrics (backend + frontend stmts/branches/funcs/lines) dropping to 0.
Root cause: `scripts/quality-gate.mjs:200-201` reads
`backend/coverage/coverage-summary.json` + `frontend/coverage/coverage-summary.json`,
both **gitignored** (`.gitignore:11-13`) and absent in this fresh dispatch
worktree. A plain `pnpm test` (root script = backend `vitest run`, no
`--coverage`) does not emit them, so `collectCoverage()` returned all-zeros.

**Fix (generate the artifacts the gate reads, no code/baseline change):**
```bash
pnpm --filter=@wahub/backend test:coverage     # → backend/coverage/coverage-summary.json
pnpm --filter=@wahub/frontend test:coverage    # → frontend/coverage/coverage-summary.json
pnpm quality-gate                              # → PASS
```
After generation the gate passed cleanly: backend stmts 94.29→94.03 (within
0.5pp tolerance), branches 87.5→88.01 (improvement), funcs 93.33→93.75; frontend
identical (80.13/82.36/72.92/80.13); test assertions 4233→4562 (+329). No
regression from W5's markdown-only diff. **`quality-baseline.json` was NOT
re-baselined** (spec Do NOT; no cause — the numbers are healthy).

## decisions for the orchestrator

1. **`factory/history.jsonl` was left untracked.** The spec scopes the backfill
   to `git add factory/missions/` (mission dossiers); `history.jsonl` is a run
   artifact, not a dossier. Per W4 it holds ~60 rows including pre-hotfix
   duplicate test snapshots (`aggregate` handles them gracefully). Options for
   the orchestrator: (a) commit as-is, (b) dedupe to last-snapshot-per-slug+state
   then commit, (c) leave untracked and let the next verdict/ratify `autoCommit`
   pick it up (its pathspec includes `factory/history.jsonl`). Until decided it
   stays untracked and visible in `git status`. It is NOT in `.gitignore`.

2. **Fresh worktrees must generate coverage before `pnpm quality-gate`.** Both
   `backend/coverage/` and `frontend/coverage/` are gitignored; a clean worktree
   has neither, so the gate sees 0% and fails. The canonical full-gate sequence
   is: `pnpm test` + both `tsc` + **both** `test:coverage` + `pnpm quality-gate`.
   (Root `pnpm test:coverage` covers backend only — frontend coverage must be
   run separately.) Consider documenting this in AGENTS.md's command list or
   wiring a root `prequality` script; out of W5 scope (Do NOT touch tooling
   outside the spec), flagged here.

3. **No structural issues surfaced** — the four features integrate cleanly.

## Deviations from spec

- **A "board-sync deliberately broken (rename)" robustness case**: the spec
  suggested renaming `board-sync.mjs` to simulate a broken hook target. I did
  NOT rename the real `scripts/factory/board-sync.mjs` in place, because
  `node --test "scripts/factory/*.test.mjs"` (the `test:factory` glob) runs
  matched test files concurrently as separate processes by default, and
  `board-sync.test.mjs` itself spawns that exact same file throughout its own
  suite. Renaming the shared production file mid-run — even briefly, inside a
  try/finally around a single synchronous `spawnSync` call — creates a real
  race window where a concurrently-running `board-sync.test.mjs` process could
  observe the file missing and fail spuriously (verified this is a live risk:
  3 consecutive `test:factory` runs above each execute all three `*.test.mjs`
  files together). Instead, the "broken hook target" scenario is reproduced by
  copying `verdict.mjs` alone (no `board-sync.mjs` beside it) into an isolated
  tmp directory and running that copy — this produces the exact same runtime
  condition the hook must tolerate (same-dir resolution finds nothing) with
  zero risk to concurrently-running tests. Verified 3× via `test:factory` that
  this does not introduce any flakiness of its own.

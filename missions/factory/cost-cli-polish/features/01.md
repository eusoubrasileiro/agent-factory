# Feature 01 — negative USD renders `-$X.XX` (mission `cost-cli-polish`)

**Seat:** claude-sonnet-4-6 builder. Pure formatting fix + tests. No secrets, no product code.

## Why

`fmtUsd(-59.5)` returns `"$-59.50"` in two places. Negative savings (the plan is losing)
is the number a reader most needs to trust; `$-59.50` reads as a typo. It must be `-$59.50`.

## Contract (write these tests FIRST — they must fail before you implement)

### `scripts/spend.mjs` — `fmtUsd`
Current:
```js
export function fmtUsd(n) {
  if (n === null || n === undefined) return "—";
  return `$${Number(n).toFixed(2)}`;
}
```
New behavior (add cases to `scripts/spend.test.mjs` first):
- `fmtUsd(-59.5) === "-$59.50"`
- `fmtUsd(-0.5) === "-$0.50"`
- Unchanged: `fmtUsd(0) === "$0.00"`, `fmtUsd(12.3) === "$12.30"`, `fmtUsd(null) === "—"`,
  `fmtUsd(undefined) === "—"`
- `-0`: `fmtUsd(-0) === "$0.00"` (no spurious sign — treat `-0` as `0`)

### `scripts/board-report.mjs` — `fmtUsd`
Current (`:740`):
```js
function fmtUsd(n) {
  return n == null || Number.isNaN(n) ? "sem dados" : `$${Number(n).toFixed(2)}`;
}
```
Same sign fix. It is currently NOT exported — **export it** so the test can reach it
(add `export` to the declaration; do not move it). Add cases to `scripts/board-report.test.mjs`:
- `fmtUsd(-59.5) === "-$59.50"`
- Unchanged: `fmtUsd(0) === "$0.00"`, `fmtUsd(null) === "sem dados"`, `fmtUsd(NaN) === "sem dados"`
- `fmtUsd(-0) === "$0.00"`

## Implementation hint

A single shared shape: compute the magnitude with `.toFixed(2)` and prepend the sign
outside the `$`. Guard `-0` by normalizing `n === 0 ? 0 : n` (or `Object.is(n,-0)`), or
simply by testing `n < 0` (which is `false` for `-0`). **Keep each function's own null
sentinel** — `"—"` for spend, `"sem dados"` for board. Do not unify them.

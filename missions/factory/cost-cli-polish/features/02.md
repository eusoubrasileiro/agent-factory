# Feature 02 — a zero plan fee means "no plan basis" in both rollups (mission `cost-cli-polish`)

**Seat:** claude-sonnet-4-6 builder. Pure aggregation fix + test. No secrets, no product code.

## Why

`spend.mjs` computes plan-$ with `planFeeUsd && periodTokens > 0` — a `0` fee is falsy →
`planUsd: null` ("no plan cost basis"). `history.mjs` computes
`planTotal = typeof planFeeUsd === "number" && safe.length > 0 ? planFeeUsd : null` — so a
`0` fee yields `planTotal: 0`. The two rollups disagree about the same input. Align
`history.mjs` to `spend.mjs`: `0` → `null`.

## Contract (write the test FIRST — it must fail before you implement)

In `scripts/history.mjs`, `aggregateScope` (`:354`):
```js
const planTotal = typeof planFeeUsd === "number" && safe.length > 0 ? planFeeUsd : null;
```
becomes (falsy-zero → null, matching spend.mjs):
```js
const planTotal = planFeeUsd && safe.length > 0 ? planFeeUsd : null;
```
`savings` already derives from `planTotal` (`costTotal !== null && planTotal !== null ? … : null`),
so it follows automatically.

Add to `scripts/history.test.mjs`:
- `aggregate(rows, { planFeeUsd: 0, missionsDir })` → the scope's `planTotal === null` AND
  `savings === null`, for a rows set that has ≥1 safe snapshot with a real `costTotal`.
- **Unchanged:** `aggregate(rows, { planFeeUsd: 72, missionsDir })` with ≥1 safe snapshot →
  `planTotal === 72` (keep/confirm an existing assertion; do not delete any).

Pick the smallest existing rows fixture in `history.test.mjs` and reuse it; do not invent a
large new one.

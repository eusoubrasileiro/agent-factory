# Feature 02 — `cage-opencode.mjs`: make Tier A real for the seat we actually run

**Seat:** GLM-5.2 builder. Pure code + test.

## Why (read this — it is the point of the feature)

`scripts/cage-settings.mjs` renders a Claude Code cage. **Nothing consumes it.** The only builder
driver we run is `opencode-worker.mjs`, and opencode does not read `.claude/settings.external.json`.
So today the Critical-File deny rules, the `git push` deny, and the `~/.ssh` deny are **not enforced
for the builder seat**. The incident that motivated the cage — a worker editing a Critical File —
is still possible.

opencode has its own permission system. Verified against opencode v1.17.15 docs
(https://opencode.ai/docs/permissions, https://opencode.ai/docs/config):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": { "*": "allow", "git push *": "deny" },
    "edit": { "*": "allow", "backend/src/bot/**": "deny" }
  }
}
```

**Last matching rule wins** — so `"*"` must come FIRST and the denies after it. Get this backwards
and the cage is inert; pin it with a test that asserts key order.

Config discovery: a project `opencode.json` has the highest precedence; `$OPENCODE_CONFIG` names a
custom path loaded between global and project config.

## Contract (tests FIRST)

New `scripts/cage-opencode.mjs`, exporting:

```js
export function renderOpencodeCage({ criticalFiles = [] } = {})   // -> settings object
export function auditOpencodeCage(settings)                        // -> string[] problems ([] = ok)
export function writeOpencodeCage(destPath, { project, factoryRoot } = {})  // -> destPath
export function opencodeCagePath(worktreeAbs)                      // -> <worktree>/.opencode-cage.json
```

`renderOpencodeCage` emits, in this exact order:
- `permission.edit`: `"*": "allow"` first; then `"<glob>": "deny"` for every profile critical file;
  then the **self-protect** entries `"opencode.json": "deny"`, `".opencode/**": "deny"`,
  `"AGENTS.md": "deny"`.
- `permission.bash`: `"*": "allow"` first; then `"git push *": "deny"`, `"git push": "deny"`.
- No `webfetch` change; do not touch `tools`.

`auditOpencodeCage` returns a problem when:
- `permission.edit` or `permission.bash` is missing or not an object;
- the FIRST key of either map is not `"*"` (order trap — last match wins);
- any self-protect entry is missing or not `"deny"`;
- `git push *` is not `"deny"`;
- any value is not one of `allow` / `deny` / `ask`.

`writeOpencodeCage` renders from `resolveProject({project}).profile.criticalFiles`, audits, and
**refuses to write** (throws) when the audit is non-empty — same fail-closed shape as
`writeCageSettings`. Reuse `resolveProject`; it is TOTAL, an unknown id degrades to `[]`.

Tests must include:
- `"*" is the first key in edit and in bash (last-match-wins ordering)`
- `every profile critical file appears as an edit deny`
- `the cage denies edits to its own config (opencode.json, .opencode/**)`
- `git push is denied`
- `renderOpencodeCage with no project emits the generic base and zero product paths`
- `writeOpencodeCage throws rather than writing a cage that fails its own audit`
- a round-trip: write to a tmpdir, read it back, `JSON.parse`, re-audit clean. Clean up in `finally`.

## Then wire it in

In `opencode-worker.mjs`, before spawn:
1. `const cage = writeOpencodeCage(opencodeCagePath(dirAbs), { project: opts.project })`
   — but write it **outside** the worktree if `TMPDIR` is available; the agent must not be able to
   edit its own cage. Prefer a temp path; fall back to the worktree only if temp creation fails.
2. Add `OPENCODE_CONFIG` to the child env (set to the rendered path).
   **`SPAWN_ENV_ALLOWLIST` does not currently include `OPENCODE_CONFIG`** — the allowlist filters
   `process.env`, so set the var on the built env object AFTER `buildSpawnEnv(process.env)` rather
   than widening the allowlist. Do not widen the allowlist.
3. If `opts.project` is absent, still write the generic base cage (git-push deny + self-protect).

Keep `buildSpawnEnv`'s contract and its existing test untouched.

## Constraints

- Plain Node ESM `.mjs`, nothing outside `node:*`. `node:test` + `node:assert/strict`, not vitest.
- No network. Do not run `opencode`. Do not install anything.
- Header comment: Usage + exit codes.
- `pnpm test` from repo root, all green, before committing.

## Explicit non-goals

the coordinator writes, because a seat must never author its own containment proof.

# Feature 01 — `lib/worker-common.mjs` + graceful kill (mission `factory-cage-usable`)

**Seat:** GLM-5.2 builder. Pure code + test, no secrets, no agent-facing prose.

## Why

`scripts/opencode-worker.mjs:307` kills a timed-out child with a straight `SIGKILL`.
We reproduced the damage on this very mission: the F2 worker committed its work, then hung;
the timer fired and `SIGKILL` took it out with no chance to flush. A worker that is mid-write
when the timer fires loses the write, and the mission loses the handoff.

`SIGKILL` cannot be caught. `SIGTERM` can — opencode flushes its session on it.

## Contract (write these tests FIRST — they must fail before you implement)

New file `scripts/lib/worker-common.mjs`, exporting:

```js
export function killGracefully(child, { graceMs = 30_000, signal = "SIGTERM" } = {})
```

Behavior:
1. Sends `signal` to `child` immediately. Returns a `Promise<{escalated: boolean}>`.
2. If the child emits `close`/`exit` before `graceMs` elapses → resolve `{escalated:false}`,
   and the escalation timer is cleared (no dangling handle — the process must be able to exit).
3. If `graceMs` elapses with no exit → send `SIGKILL`, resolve `{escalated:true}`.
4. Calling it on an already-exited child must not throw (`child.kill` on a dead pid throws
   `ESRCH` in some node versions — guard it).
5. `graceMs = 0` → escalate immediately (used by tests; do not busy-wait).

Test it with a **real child process**, not a mock: `spawn(process.execPath, ["-e", "..."])`.
- A script that traps SIGTERM and exits promptly → `escalated:false`.
- A script that ignores SIGTERM (`process.on('SIGTERM',()=>{})`) plus a live timer → `escalated:true`,
  and assert the process is actually gone afterwards.
- Always `finally { try { child.kill('SIGKILL') } catch {} }` so a failing test never leaks a process.

## Then wire it in

In `scripts/opencode-worker.mjs`, replace the `child.kill("SIGKILL")` at the timeout with
`await killGracefully(child, { graceMs: 30_000 })`. Keep `timedOut = true` semantics and the
`exitCode: timedOut ? 1 : (code ?? 1)` mapping exactly as they are — the mission contract
depends on a timeout reporting exit 1.

Do not change the default timeout. Do not change `buildSpawnEnv`, `isWorktreeDir`, or arg parsing.

## Constraints

- Plain Node ESM `.mjs`. No dependency outside `node:*`.
- `node:test` + `node:assert/strict`. **Not vitest.**
- Header comment with Usage + exit codes, per house style.
- Keep the `isMain` guard shape used by sibling scripts.
- Run `pnpm test` from the repo root. ALL green before you commit.

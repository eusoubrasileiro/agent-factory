# Decision Log (append-only)

> Replaces the retired `docs/adr/` forest. **One line per real decision.** Append only —
> never edit or delete a past line (that is how a contradiction gets back in). Only record a
> decision that is **hard to reverse**, **surprising without context**, and **a real
> trade-off**. Everything else lives in the git history.
>
> Format: `- YYYY-MM-DD · D-NN · <the decision> — <why, one clause>. [supersedes D-MM]`

This file is one of the four named authorities (`constitution.md`, `RUNBOOK.md`,
`decisions.md`, `README.md`) enforced by `scripts/docs-law.test.mjs`. It is the answer to
"why is it like this?" for every agent seat that reads this repo.

Rules this file is held to:

1. **Append-only.** A superseded decision is not deleted; a later line supersedes it and says
   so (`supersedes D-NN` / `corrects D-NN`). The contradiction stays visible.
2. **A decision names its ratifier.** Agents propose; André ratifies. A line without a
   ratifier is a proposal and belongs in `decisions.inbox.md` until it is ratified.
3. **Evidence, not assertion.** A decision settled by a measurement cites the measurement.
   "It felt slow" is not a decision record.
4. **No live surface cites archived text** (rule 3 of the doc law). A spent plan's durable
   outcome lands here as one line; the plan itself dies in the archive.

Note on this translation: the ledger was written in Portuguese as work happened and was
translated for publication. IDs and dates are preserved exactly, including the duplicate
IDs that D-50 documents and the gaps that the history actually contains. Client-identifying
detail has been replaced by the mechanism it illustrates; nothing else was rewritten.
